## 它解决什么问题

你让 AI 排过行程吗?它会热情地给你一篇小作文:景点是真的,营业时间是编的;路线在地图上画出来是个"米"字;机票价格停留在它的训练数据里;酒店推荐抄的是商家简介,不是住客差评。

这个 skill 换了一个思路:**行程不是写出来的,是查证出来的。** 它跑一个四段工作流——先把需求 **grill 透**(沿决策树逐层追问:大交通订了没?返程几点前必须到家?证件在不在有效期?——每问附推荐答案,问到没有一项靠猜为止),再检索交通/天气/开放时间(含小红书攻略,但会鉴别软广、只采多篇互证的经验),然后逐项核对(闭馆日、赶车缓冲、日落时间),最后才组装页面。每个数字要么来自当场检索或浏览器实价,要么老老实实标「以官网为准」。机票和酒店价格走浏览器多平台实查(只读,绝不下单);酒店评论**双信源交叉**——携程 + 高德都读一遍,携程光鲜但高德有复发吐槽就信高德;打车里程时长去高德路线实跑,不拍脑袋。

产出是**一个自包含 HTML 文件**:发给同行人就能用,旅途中手机离线打开,勾掉的清单项都记得住。

老人家走不动太多路,节奏悠闲点,帮我做个行程。

| 逐日时间线 + 交通段卡 | 住宿备选(评论体检) | 手机端 |
|---|---|---|
| ![timeline](assets/timeline-desktop.png) | ![hotels](assets/hotels-desktop.png) | ![mobile](assets/mobile.png) |

注意截图里的细节:机票按「实查裸价 + 现查税费」口径标总价(国内全平台列表价都是裸价、无一例外,燃油附加费还随油价频繁调整——直接拿列表价做预算必然失真);推荐的两班直飞(HO1119/HO1060)**携程当日没在卖**,飞猪和官网在卖且**全是裸价**(吉祥官网页头标"含税"但订单页实测仍另加 ¥200 税费)——比价必须先统一到"裸价+税费"口径;市内打车费按**高德实测里程 × 成都出租车计价标准**估算并写明来源;查不到的数字(飞猪验证码墙后的那家)如实标「未读价」。实查还推翻了一串想当然:初稿推荐的一家如家分店在携程查无此店、「华住会会员价更低」实测是迷思、"上午没有直飞"是上一版漏读官网渠道的错误结论。这就是"查证型行程页"和"写出来的攻略"的区别。

**对照实验**(2 个中文用例,同 prompt 跑 with/without skill,[完整数据](evals/benchmark.md)):

| 配置 | 自动检查 | HTML 校验 | 地图 | 主题头 | POI 四字段卡 |
|---|---|---|---|---|---|
| **with skill** | **10/10 ×2** | 全过 | ✅ | ✅ | ✅ |
| baseline(无 skill) | 5/10 ×2 | FAIL ×2 | ❌ | ❌ | ❌ |

成本如实说:with-skill 约 2× tokens 和耗时(~10 万 tokens / 7–8 分钟)——这是真检索 + 完整结构化构建的价格。

## 快速开始

一行安装(推荐):

```bash
npx skills add ErikaAlk/trip-planner
```

或手动克隆:

```bash
git clone https://github.com/ErikaAlk/trip-planner ~/.claude/skills/trip-planner
```

装完对 Claude Code 说(可直接复制):

```text
国庆想去西安玩4天,从北京出发,帮我做个行程
```

零 API key 也能跑:地图用 Leaflet + OpenStreetMap(免 key),检索用 Agent 自带的 web search,浏览器比价在有 Chrome 连接时自动启用、没有就降级为标注过的估价。

### 可选:配一把腾讯位置服务 Key(强烈建议)

配了之后,**坐标、车程、公交票价不用再一个个手点地图网站**——一条命令批量查完,而且脚本会把查不到的点明确标成查不到,不会拿个相近的地方糊弄过去。不配也能用,只是退回浏览器逐段点。

1. **免费申请**:打开 [lbs.qq.com 控制台](https://lbs.qq.com/dev/console/application/mine) → 登录 → 应用管理 → 我的应用 → 创建应用 → 添加 Key
2. **启用 WebServiceAPI**,授权方式选「无」,或把本机公网 IP 加进白名单
   - ⚠ **别开签名校验(SK)** —— 脚本不支持,已经开了就另建一把不开签名的
3. **把 Key 放到本机**(二选一,都不进仓库):

   ```bash
   # 用户级,配一次长期有效
   echo "你的KEY" > ~/.claude/.tencent-lbs-key
   ```

   ```powershell
   # 或者只在当前终端生效
   $env:TENCENT_LBS_KEY = "你的KEY"
   ```

4. **验证**:

   ```bash
   python3 scripts/tencent_lbs.py selfcheck
   ```

   四项全绿(地点搜索 / 驾车路线 / 距离矩阵 / 误报防护)就算配好了。没配 Key 直接跑会打印申请步骤,不会报一个看不懂的错。

**额度**:个人开发者 10,000 次/日、5 次/秒([官方配额页](https://lbs.qq.com/webservice_v1/guide-quota.html)),一次行程规划大约几十次调用,够用。
**Key 不要提交进任何仓库** —— 脚本只从环境变量和上面那个文件读,本仓库不存任何 Key。

### 可选:配一把 Exa Key(补门票/开放时间/预约)

门票、开放时间、预约配额这几样,以前只能写「以官网为准」。配了 Exa 之后,`exa_facts.py` 会去找**官方页**并把**页面原文**取回来,你读了再写值。实测拿到了大熊猫基地的「限流 8.5万人次/日」「提前 14 日预订」「成人票 55 元」。

> ⚠ **Exa 按次计费,不是免费额度。** 实测 `/search` $0.007、`/contents` $0.001、`/answer` $0.005。每条命令都会打印本次花费,批量跑请带 `--budget` 设上限。

1. 申请与用量:[dashboard.exa.ai](https://dashboard.exa.ai)
2. 放 Key(二选一,都不进仓库):

   ```bash
   echo "你的KEY" > ~/.claude/.exa-key
   ```

   ```powershell
   $env:EXA_API_KEY = "你的KEY"
   ```

3. 验证(约 $0.008):

   ```bash
   python3 scripts/exa_facts.py selfcheck
   ```

**也可以装成 MCP**(全局可用,不限于本 skill),官方走 OAuth、不需要上面这把 Key:

```bash
claude mcp add --transport http exa https://mcp.exa.ai/mcp
```

装完要在交互式会话里完成一次浏览器授权。⚠ **但中文查询建议仍走本 skill 的脚本**:实测同一句中文在**未授权**的 `mcp.exa.ai` 上返回的是完全无关的维基百科词条(英文查询正常),授权后中文表现如何请自己验一次再依赖它。

> **提效小贴士(强烈建议):** 跑之前在 Chrome 里**提前登录好携程、飞猪、高德(登录后切到新版地图)、以及常用航司官网**,能显著减少中途的登录墙/验证码打断,比价和评论查得更全更快。**飞猪弹验证码的概率很高**——查飞猪时多留意,触发了就在标签页里过一下(Agent 不会替你过验证码)。

## 它会交付什么

一个自包含 HTML 行程页,包含:主题化渐变头部(按目的地配色)、内嵌 Leaflet 地图(逐日编号 pin + 路线)、逐日 POI 时间线卡(到达时间/停留/票价/营业时间)、点间通勤连接器(步行/地铁/打车 + 距离 + 时间)、每日花费与步数估算、交通段卡(航班/车次 + 多平台比价)、**≥3 张住宿备选卡(评论体检 + 比价,用户没提酒店也会有)**、按天小计的预算表、localStorage 出发前清单、雨天 Plan B,以及 注意/必订/避雷 callout。

## 它和同类有什么不同

| 维度 | 同类常见做法 | 本 skill |
|---|---|---|
| 地图 | 无地图,或跳转链接([ycyliu](https://github.com/ycyliu/travel-planner-skill)、[SunDaysketch](https://github.com/SunDaysketch/travel-planner-skill)),或要 API key + 本地服务器([sucr233](https://github.com/sucr233/travel_planner_skills)) | 内嵌 Leaflet + OSM,免 key,单文件离线可看 |
| 价格数据 | 硬编码在 skill 里(会过期),或模型记忆 | 浏览器多平台实查;国内机票全平台均为裸价,统一按「裸价+现查税费」口径比价;查不到就标「以官网为准」,不编 |
| 酒店推荐 | 抄商家简介和评分 | 读最近差评做「评论体检」,评论压过品牌 |
| 预订 | 部分同类可直接下单 | **只查询,永不下单/登录/过验证码**——预订永远是你自己的动作 |
| 输出验证 | 无 | 静态校验器把关:地图坐标、组件齐全、自包含,缺住宿卡直接 FAIL |

## 安全边界

- **不编数字(数据诚信契约·凌驾一切)**:每个具体值——评分/票价/营业时间/车次/打车费/天气/坐标——要么本会话实查到并标来源,要么写成不含杜撰细节的 hedge(以官网为准/以高德为准/评分以App为准)。**宁可不写,绝不编。** 没浏览器读到评论区,就不写评分数字、不下「可信/已核」结论。

- **只读不订**:永不下单、付款、占座;预订链接给你,动作你来做。
- **永不碰你的凭据**:不输密码、不解验证码/滑块。遇登录墙会把标签页停在登录页、攒成一批请你登录一次,然后只做"读价"。
- 不删改你的文件,只在你指定的目录写一个 HTML。

## 验证与测试

拿 [evals/evals.json](evals/evals.json) 里的 prompt 跑一遍,合格的产物应当一次通过:

```bash
py scripts/check_html.py 成都4日游行程.html   # Windows
python3 scripts/check_html.py <输出>.html      # macOS/Linux
```

校验器检查:`<div>` 平衡、Leaflet 接线、每个地图点的数字坐标、无模板残留、自包含、以及旅行组件是否真实落地(≥3 住宿卡/预算表/清单)。对照实验方法与数据见 [evals/benchmark.md](evals/benchmark.md)。

腾讯位置服务脚本另有一套离线测试,**不联网、不需要 Key**,可直接跑:

```bash
python3 scripts/test_tencent_lbs.py     # 28 项:坐标转换/相关性判定/Key 查找/限流/无硬编码密钥
python3 scripts/test_exa_facts.py       # 26 项:关键词定位/来源排序/预算闸/无硬编码密钥
```

其中三项是专门用来挡回归的:坐标转换被改成空操作会红、相关性拦截被放宽会红、源码里出现真实 Key 形状的字面量会红。联网部分由 `tencent_lbs.py selfcheck` 覆盖。

## 更新记录

- **2026-08-25 · v0.22.1** — SKILL.md 新增「中文文风：别写出 AI 腔」一节。
  - **为什么**：行程页的视觉在 v0.19 已经从「只换顶部横幅」改成整页可选方向，文字这层一直没管。
    「必订 / 避雷」那些 callout 里全是破折号和加粗短句，读起来像旅游宣传页而不是给自己看的行程。
  - **六条**：破折号别当万能连接词；加粗一段最多点一两个词；标题后面不挂解释；emoji 不做装饰
    （callout 自带的语义图标不算）；不写三连排比和升华结尾；不确定就写「未核实」。
  - **自检**：交付前把全文的 `——`、`**`、装饰性 emoji 各数一遍。要更细的清单读 `humanizer` skill。

- **2026-08-18 · v0.22** — 接入 Exa，补上契约里最后一格纯 hedge 的数据：门票 / 开放时间 / 预约配额。
  - **为什么**:这几样一直只能写「以官网为准」——官方页难找,`web_search` 给的是摘要而不是可引用的页面原文。
  - **新增 `scripts/exa_facts.py`**:`verify`(找官方页并给原文)、`fetch`(抓指定 URL,$0.001 最便宜)、`search`(可 `--site` 限定小红书/点评)、`answer`(仅用于定位来源)、`selfcheck`。
  - **它故意不做总结**。返回官方页自己的文字 + URL,由你读了再写值。实测拿到了以前写不出来的东西:大熊猫基地「限流 8.5万人次/日」「提前 14 日预订」「11月至次年2月上午票 8:00-12:00」「成人票 55 元」。
  - **`answer` 明确不算来源**:它返回 Exa 模型综合的流畅答案(实测质量不错、带 8 条引用),但那是二手的,抄进行程等于把模型总结洗成「已核实」。只用它定位候选 URL。
  - **关键词定位**:官方页开头是几百字导航菜单,而菜单里也含「开放时间」「票务服务」这些词。判据是**真事实句带数字、菜单不带**,据此过滤,实测干掉整块导航只留票务正文。
  - **中文必须走 REST + Key**:同一句中文查询,匿名 `mcp.exa.ai` 返回的是无关的维基百科**元音音标**词条,英文查询则正常。匿名 MCP 在中文上会静默退化。
  - **花钱,所以有预算闸**:实测 `/search` $0.007、`/contents` $0.001、`/answer` $0.005。每条命令都打印花费,`--budget` 在超限前拦住。
  - **顺手修了一个文档级 bug**:`--key`/`--json` 原来只挂在顶层,于是 v0.21 写进 SKILL.md 的示例 `geocode --file x --city 成都 --json` **照着跑会直接失败**。改为挂在子命令上,并加测试断言文档里的命令形式能被解析。
  - 测试 `scripts/test_exa_facts.py` 26 项(离线、不需要 Key、不花钱),5 条变异全部被抓住。

- **2026-08-18 · v0.21** — 接入腾讯位置服务 WebService API,把 Step 3.5 里"逐个去地图网站点"的活儿换成一条命令。
  - **为什么**:坐标、车程、公交票价这几样一直靠浏览器手点,慢且容易半途失败;坐标更是长期靠"知名点的已知坐标",查不到就只能降级。现在这些都有确定性来源了。
  - **新增 `scripts/tencent_lbs.py`**(标准库,无第三方依赖):`geocode` 批量取坐标、`route` 查驾车/公交/步行(带票价与过路费)、`matrix` 出距离矩阵做地理聚类、`search` 找周边、`selfcheck` 自检。
  - **坐标系是这次最关键的一个坑**:腾讯返回 **GCJ-02**,而本 skill 的地图是 Leaflet + OpenStreetMap(**WGS-84**)。直接填进去每个点都会偏——实测东方明珠差 **502 米**,正好错开一条街。脚本默认输出 WGS-84,转换算法与腾讯自家的坐标转换接口对过,往返误差 **0.00 米**。
